## პრობლემის ჩამოყალიბება

### ბიზნეს პრობლემა და მიზანი
ვადაგადაცილებული სესხების მართვის დეპარტამენტის პორტფელში არსებობს უიმედო სესხები (120+ დღით ვადაგადაცილებული). ისტორიულად, სასამართლოში საქმის გადაცემის გადაწყვეტილება მიიღებოდა ექსპერტული წესების საფუძველზე. ვინაიდან სამართალწარმოება ხანგრძლივი და ძვირადღირებული პროცესია, ხოლო რესურსები შეზღუდულია, ბანკის მიზანია ექსპერტული წესების ჩანაცვლება მანქანური სწავლების (Machine Learning) მოდელით.
მოდელის ძირითადი ამოცანაა წინასწარ იპროგნოზოს, რომელ კლიენტებზე იქნება სასამართლო პროცესის დაწყება ფინანსურად მომგებიანი (ანუ საიდანაც ამოღებული თანხა გადაფარავს სასამართლო ხარჯებს და მოიტანს წმინდა მოგებას).

### სამუშაო არეალი და ბიზნეს შეზღუდვები
სამუშაო არეალი: მოდელი გამოიყენება მხოლოდ არაუზრუნველყოფილ სესხებზე (HAS_COLLATERAL == 0 / COLLATERAL_TYPE == 'NONE'). უზრუნველყოფილი სესხების ამოღება ხდება ქონების რეალიზაციით სხვა დეპარტამენტის მიერ. გადაწყვეტილების დონე (Granularity): გადაწყვეტილება მიიღება კლიენტის დონეზე (CLIENT_KEY + PERIOD). თუ გადაწყდა კლიენტთან სამართალწარმოების დაწყება, პროცესი იწყება მის ყველა აქტიურ არაუზრუნველყოფილ სესხზე.
სასამართლო ხარჯების სტრუქტურა:
თითოეულ სესხზე სასამართლოში გადაცემის ფიქსირებული და ცვლადი ხარჯი შეადგენს:
 (Legal Cost)_i = 500 + 0.10  X (OUTST_AT_TRIAL)_i
სადაც 500 ლარი არის ფიქსირებული განაკვეთი, ხოლო 10% — სესხის ნარჩენი ძირითადი თანხა.

### ფინანსური შეფასების მატრიცა და ოპტიმიზაციის მეტრიკა
მოდელის შეფასება არ უნდა მოხდეს მხოლოდ სტანდარტული ML მეტრიკებით (ROC-AUC, RMSE), არამედ პირდაპირი ფინანსური წმინდა მოგებით (Net Financial Profit).
კლიენტისთვის i-სთვის 24 თვის განმავლობაში ჯამური ამოღებული თანხა არის Recovery_i, ხოლო ჯამური სასამართლო ხარჯი — (Legal Cost)_i.
წმინდა მოგება->Recovery_i- (Legal Cost)_i.

კლიენტს ვუჩივლებთ სასამართლოში, თუ მოდელის მიერ პროგნოზირებული წმინდა მოგება დადებითია. 
Total Net Benefit (ჯამური წმინდა სარგებელი):ჯამი ყველა i-ური კლიენტის წმინდა მოგეისა.
ROI (Return on Investment): წმინდა მოგება/ ბანკის მიერ გაწეული სასამართლო ხარჯი (i-ურ კლიენტზე). -> გვიჩვენებს დახარჯული 1 ლარიდან რამდენ პროცენტს ვშოულობთ ზემოდან წმინდა მოგებად.  დახარჯული სასამართლო ხარჯის რამდენ პროცენტს ვშოულობთ წმინდა მოგებად.

მაღალი ROI პირდაპირ მიუთითებს ჩადებული კაპიტალის მაღალ ეფექტიანობაზე, თუმცა ბიზნესში ოპტიმალური გადაწყვეტილების მისაღებად ის ჯამურ წმინდა მოგებასთან  კომბინაციაში უნდა შეფასდეს. 

### სამიზნე ცვლადის (Target Variable) განსაზღვრის სტრატეგია
ვინაიდან მონაცემებში გვაქვს დროითი ცენზურირება (MONTHS_OBSERVED მერყეობს 6-დან 24 თვემდე), სამიზნე ცვლადის აგებისას განხილული იქნება 2 მიდგომა:
კლასიფიკაციის მიდგომა - 1 თუ კლიენტმა დაფარა თავისი სასამართლო ხარჯი მაინც, 0 თუ ბანკი ზარალში დარჩა.
რეგრესიის მიდგომა - მოდელი აპროგნოზებს ამოღების პროცენტს (Recovery Rate->გვეუბნება სესხის დავალიანების რამდენ პროცენტს ვიბრუნდებთ) ან აბსოლუტურ ამოღებულ თანხას, რის შემდეგაც ფინანსური წესი აფასებს მომგებიანობას.

## დატის დამუშავება
loans მოიცავს 70,173 ჩანაწერს და 33 სვეტს.

კრიტიკული დაკვირვება: loans ცხრილში სტრიქონების რაოდენობა ~2.36-ჯერ მეტია features-ზე, რაც მიუთითებს იმაზე, რომ loans წარმოდგენილია სესხების დონეზე, ხოლო features — კლიენტი-პერიოდის დონეზე. ანუ გამოდის რომ ერთ კლიენტს კონკრეტულ მომენტში რამდენიმე სესხი აქვს:
როდესაც ბანკი კლიენტზე იწყებს სასამართლო პროცესს (PERIOD), იმ მომენტში კლიენტს საშუალოდ ~2.36 სესხი აქვს აქტიური. კლიენტი მონაცემებში შეიძლება დროის სხვადასხვა პერიოდშიც შეგვხვდეს:
სულ გვყავს 22,000 უნიკალური კლიენტი, მაგრამ 29,763 უნიკალური ეპიზოდი (CLIENT_KEY, PERIOD). ეს ნიშნავს, რომ ზოგიერთი კლიენტი სხვადასხვა დროს (სხვადასხვა PERIOD-ში) ხელახლა მოხვდა სასამართლო გადაწყვეტილების მიღების პროცესში.

M01_PAID-დან M06_PAID-მდე ყველა ჩანაწერი შევსებულია (70,173 არაცარიელი ჩანაწერი).

M07_PAID-დან იწყება NaN (გამოტოვებული) მნიშვნელობები, რომლებიც ეტაპობრივად იზრდება M24_PAID-მდე.

ეს დინამიკა არ არის ხარვეზი — ეს გამოწვეულია იმით, რომ ახალ კლიენტებს ჯერ არ გასვლიათ 24 თვე სასამართლოს დაწყებიდან. ესენი  არის დროის ფარდობითი (შეფარდებითი) თვეები სასამართლოს დაწყების მომენტიდან. M02_PAID — სასამართლოს დაწყებიდან მე-2 თვეს გადახდილი თანხა ლარში...

რას აკეთებს კოდი: ითვლის რიცხვითი ცვლადების ძირითად სტატისტიკურ პარამეტრებს (Mean, Std, Min, Quantiles, Max).

რატომ გავაკეთეთ: ასიმეტრიის (Skewness), ექსტრემალური მნიშვნელობების (Outliers) და მონაცემთა განაწილების მასშტაბების შესაფასებლად.

რა გავიგეთ Output-იდან:

ფინანსური სვეტები (OUTST_AT_TRIAL, DEAL_PRINCIPAL_IN_GEL) ხასიათდება ძლიერი მემარჯვენე ასიმეტრიით (საშუალო მნიშვნელოვნად აღემატება მედიანას).

დაფარვების დინამიკა დროში მცირდება: ყველაზე მაღალი თანხების ამოღება ხდება პირველ თვეებში, ხოლო შემდგომ ტემპი ნელდება.


ითვლის უნიკალურ კლიენტებს, უნიკალურ სესხებს და უნიკალურ წყვილებს (CLIENT_KEY, PERIOD) ორივე ცხრილში.

რატომ გავაკეთეთ: ეს არის პროექტის ყველაზე კრიტიკული ნაბიჯი მონაცემთა არქიტექტურის დასადგენად.

რა გავიგეთ Output-იდან (მნიშვნელოვანი მიგნება):

ორივე ცხრილში არის ზუსტად 29,763 უნიკალური წყვილი (CLIENT_KEY, PERIOD).

იყენებს სიმრავლეების (Sets) გადაკვეთას და სხვაობას, რათა შეამოწმოს, არსებობს თუ არა კლიენტ-პერიოდი, რომელიც ერთ ცხრილშია და მეორეში არა.

რა გავიგეთ Output-იდან: არსებობს 100%-იანი თანხვედრა. არცერთი ჩანაწერი არ იკარგება და არც ზედმეტი აცდენილი ჩანაწერი გვხვდება.

## 1. პრობლემის ჩამოყალიბება და ბიზნეს კონტექსტი

### 1.1. ბიზნეს პრობლემა და მიზანი

სამუშაოს დასაწყისში პირველ რიგში დეტალურად შევისწავლე ვადაგადაცილებული სესხების მართვის დეპარტამენტის წინაშე არსებული ამოცანა. პორტფელში არსებობს უიმედო სესხები, რომლებმაც მიაღწიეს 120+ დღიან ვადაგადაცილებას. ისტორიულად, ბანკში ექსპერტული წესებით წყდებოდა, თუ რომელ კლიენტზე დაწყებულიყო სასამართლო წარმოება. ვინაიდან სამართალწარმოება ხანგრძლივი და ძვირადღირებული პროცესია, ხოლო ბანკის რესურსი — შეზღუდული, გადავწყვიტე შემექმნა მანქანური სწავლების (Machine Learning) მოდელზე დაფუძნებული გადაწყვეტილების მიღების სისტემა.

ჩემი მთავარი მიზანია წინასწარ ვიპროგნოზო, **რომელ კლიენტებზე იქნება სასამართლო პროცესის დაწყება ფინანსურად მომგებიანი** — ანუ საიდან ამოღებული თანხაც გადაფარავს სასამართლო ხარჯებს და ბანკს მოუტანს წმინდა მოგებას.

### 1.2. სამუშაო არეალი და ბიზნეს შეზღუდვები

ანალიზისას გავითვალისწინე ბიზნესის მიერ დაწესებული ძირითადი შეზღუდვები:

* **სამუშაო არეალი:** მოდელს გამოვიყენებ **მხოლოდ არაუზრუნველყოფილ სესხებზე** (`HAS_COLLATERAL == 0` / `COLLATERAL_TYPE == 'NONE'`), რადგან უზრუნველყოფილ სესხებს ქონების რეალიზაციით სხვა დეპარტამენტი მართავს.


* **გადაწყვეტილების გრანულარობა (Granularity):** გადაწყვეტილება მიიღება **კლიენტისა და პერიოდის დონეზე** (`CLIENT_KEY` + `PERIOD`). თუ გადავწყვეტთ კლიენტთან ჩივილს, პროცესი იწყება მისი ყველა აქტიურ არაუზრუნველყოფილ სესხზე.


* **სასამართლო ხარჯების სტრუქტურა:** თითოეულ სესხზე გაიღება ფიქსირებული და ცვლადი ხარჯი:



$$\text{Legal Cost}_i = 500 + 0.10 \times \text{OUTST\_AT\_TRIAL}_i$$



სადაც **500 ლარი** არის ფიქსირებული განაკვეთი, ხოლო **10%** — სესხის ნარჩენი ძირითადი დავალიანება.

### 1.3. ფინანსური შეფასების მატრიცა და ოპტიმიზაციის მეტრიკა

გადავწყვიტე, რომ მოდელი არ შევაფასო მხოლოდ სტანდარტული ML მეტრიკებით (ROC-AUC, RMSE), არამედ პირდაპირი ფინანსური სარგებლით.

კლიენტისთვის $i$, 24 თვის განმავლობაში ამოღებული ჯამური თანხა არის $\text{Recovery}_i$, ხოლო გაწეული ჯამური სასამართლო ხარჯი — $\text{Legal Cost}_i$.

* **წმინდა მოგება (Net Profit):** $\text{Net Profit}_i = \text{Recovery}_i - \text{Legal Cost}_i$

* **გადაწყვეტილების წესი:** კლიენტს ვუჩივლებთ სასამართლოში, თუ მოდელის მიერ პროგნოზირებული წმინდა მოგება დადებითია ($\mathbb{E}[\text{Net Profit}_i] > 0$).
* **პორტფელის ოპტიმიზაციის მეტრიკები:**
1. **Total Net Benefit (ჯამური წმინდა სარგებელი):** შერჩეული კლიენტების წმინდა მოგებების ჯამი.
2. **ROI (Return on Investment):** $\frac{\sum \text{Net Profit}_i}{\sum \text{Legal Cost}_i}$ — გვიჩვენებს, სასამართლოზე დახარჯული ყოველი 1 ლარიდან რამდენ პროცენტს ვშოულობთ ზემოდან წმინდა მოგებად.



> **ბიზნეს დაკვირვება:** მაღალი ROI მიუთითებს კაპიტალის მაღალ ეფექტიანობაზე, თუმცა საბოლოო გადაწყვეტილების მისაღებად ის ჯამურ წმინდა მოგებასთან ($\sum \text{Net Profit}$) კომბინაციაში უნდა შევადგინო, რათა არ მოხდეს პორტფელის ზედმეტად შეზღუდვა.

---

### 1.4. სამიზნე ცვლადის (Target Variable) განსაზღვრის სტრატეგია

ვინაიდან მონაცემებში გვაქვს დროითი ცენზურირება (`MONTHS_OBSERVED` მერყეობს 6-დან 24 თვემდე), განვიხილავ 2 მიდგომას:

1. **კლასიფიკაცია:** 1 — თუ კლიენტმა დაფარა თავისი სასამართლო ხარჯი მაინც ($\text{Recovery}_i > \text{Legal Cost}_i$), 0 — თუ ბანკი ზარალში დარჩა.


2. **რეგრესია (ექსტრაპოლაციით):** მოდელი აპროგნოზებს ამოღების პროცენტს (Recovery Rate = $\text{Recovery}_i / \text{OUTST}_i$) ან აბსოლუტურ ამოღებულ თანხას, რის შემდეგაც ფინანსური წესით ვაფასებ მომგებიანობას.

### 3.1. არაუზრუნველყოფილი პორტფელის აგრეგაცია კლიენტი-პერიოდის დონეზე

ბიზნეს ლოგიკის შესაბამისად, არაუზრუნველყოფილი სესხები დავაგრეგირე `(CLIENT_KEY, PERIOD)` დონეზე:

```python
paid_cols = [f'M{i:02d}_PAID' for i in range(1, 25)]
unsecured_loans = loans[loans['HAS_COLLATERAL'] == 0].copy()

agg_rules = {
    'OUTST_AT_TRIAL': 'sum',
    'LOAN_KEY': 'count',
    'MONTHS_OBSERVED': 'first'
}

episodes = (
    unsecured_loans.groupby(['CLIENT_KEY', 'PERIOD'])
    .agg(agg_rules)
    .rename(columns={'LOAN_KEY': 'n_unsec_loans'})
)

monthly_paid = unsecured_loans.groupby(['CLIENT_KEY', 'PERIOD'])[paid_cols].sum(min_count=1)
episodes = episodes.join(monthly_paid).reset_index()

```

> **ტექნიკური დეტალი:** `min_count=1`-ის გამოყენებით უზრუნველვყავი, რომ თუ კონკრეტული თვის დაფარვა ყველა სესხზე `NaN`-ია (დროითი ცენზურირების გამო), ჯამიც დარჩეს `NaN` და არ გადაიქცეს მცდარ `0.0`-ად.

**აგრეგაციის შედეგები:**

* არაუზრუნველყოფილ პორტფელში მივიღე **27,031 ეპიზოდი** (კლიენტ-პერიოდის წყვილი) **20,635 უნიკალურ კლიენტზე**.

* ამოვიღე მხოლოდ 2 ეპიზოდი `OUTST == 0`-ით.
* კლიენტის დონეზე საშუალო დავალიანება სასამართლოს დაწყებისას შეადგენს **7,025.61 GEL**-ს, ხოლო მედიანა — **4,463.98 GEL**-ს (მაქსიმუმი: **180,542.79 GEL**).

### 3.2. მომწიფებული კოჰორტების (24m) ანალიზი და მულტიპლიკატორი

იმისთვის, რომ შემექმნა მეთოდოლოგია არასრულად მომწიფებული კოჰორტების 24-თვიანი ამოღების საპროგნოზოდ, გამოვყავი სრულად "მომწიფებული" ეპიზოდები (`MONTHS_OBSERVED == 24`, სულ 11,560 ეპიზოდი) და გამოვითვალე 12-თვიანი და 24-თვიანი ამოღების მაჩვენებლები:

* **12-Month Recovery Rate ($\text{Rec}_{12m} / \text{OUTST}$):** **0.0876 (8.76%)**
* **24-Month Recovery Rate ($\text{Rec}_{24m} / \text{OUTST}$):** **0.1231 (12.31%)**
* **12m to 24m Multiplier ($K_{24/12}$):**

$$K_{24/12} = \frac{\sum \text{Recovery}_{24m}}{\sum \text{Recovery}_{12m}} = \frac{0.1231}{0.0876} = \mathbf{1.405}$$



**ჩემი კრიტიკული მიგნება:** $K_{24/12} = 1.405$ მულტიპლიკატორი გვიჩვენებს, რომ კლიენტი მომდევნო 12 თვეში (13–24 თვეები) საშუალოდ ამატებს პირველ წელს ამოღებული თანხის **~40.5%-ს**. ეს გვაძლევს მათემატიკურ საფუძველს, რომ არასრულად მომწიფებული კოჰორტების 12-თვიანი მონაცემები დავაექსტრაპოლიროთ 24-თვიან სამიზნეზე.
